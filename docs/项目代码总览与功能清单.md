# CourseMate 项目代码总览与功能清单

整理日期：2026-11-05。依据当前工作区的页面、路由、应用服务、领域规则和内容文件，包含尚未提交的课堂签到等改动；不代表生产服务器已经更新。当前版本文件为 `0.4.4-beta.3`。

## 1. 项目定位

课知伴是面向《信号与系统》课程的教学平台，覆盖“知识学习 → 实验探究 → 练习与测验 → 错题复习 → 教师查看反馈”，同时提供课堂签到、班级管理、AI 对话和资料知识库。

当前代码包含 42 个 Next.js 页面入口、10 个前端功能目录和 25 个后端应用模块。页面入口数量不等于独立功能数量：部分页面是兼容链接、跳转页或桌面壳页面。

## 2. 代码结构与职责

| 路径 | 职责 |
| --- | --- |
| `apps/web/app/` | Next.js 页面与布局，保持路由层轻量。 |
| `apps/web/features/` | `learning` 学习实验、`classrooms` 班级课堂、`chat` 对话、`knowledge-bases` 资料库、`admin` 后台、`auth` 登录、`settings` 设置、`recent` 最近对话、`shell` 导航、`desktop` 桌面接入。 |
| `apps/web/shared/`、`entities/`、`components/` | API 调用、登录状态、平台适配、通用工具、业务实体和基础 UI。 |
| `apps/web/i18n/` | 中文与英文界面文案；课程正文主要为中文，不能据此认定所有教学材料都有英文版。 |
| `apps/web/public/vendor/signal-lab/` | 实验数值引擎、当前任务规则、历史版本兼容与实验资源。当前引擎版本为 `1.2.0`。 |
| `apps/web/public/learning/python/` | Python 脚本、Notebook、资源包及说明。 |
| `backend/cmd/server/`、`internal/app/` | Go 服务入口、依赖装配、服务启动和关闭。 |
| `backend/internal/transport/http/` | Gin 路由、鉴权中间件、请求校验和对外 DTO。 |
| `backend/internal/application/` | 用例编排：班级、签到、学习、评分、对话、文件、配置等。 |
| `backend/internal/domain/` | 题目、评分、复习间隔、权限和实体等业务规则。 |
| `backend/internal/repository/`、`ports/`、`infra/` | 存储与外部服务接口，以及数据库、缓存、模型协议、文件解析等实现。 |
| `backend/docs/`、`packages/api-contract/` | Swagger 与生成的 TypeScript API 类型。 |
| `packages/core/` | 无 UI、无平台 I/O 的鉴权续期、服务地址和能力解析逻辑。 |
| `apps/desktop/` | Tauri 2 / Rust 桌面壳，复用网页与 Go 服务。 |
| `content/signals/` | 课程原始材料、整理后的知识笔记和内容生成依据。 |
| `scripts/`、`deploy/`、`.github/workflows/` | 内容生成、校验、Docker 部署、可选服务和构建发布流程。 |

主要技术：Next.js 16、React 19、TypeScript、Tailwind CSS、Go / Gin / GORM、Tauri 2。开发时前后端分开启动；部署时可将前端静态文件交给 Go 服务统一提供。

主要数据流：页面 → 功能组件与 Hook → API → HTTP 处理器 → 应用服务 → 领域规则与存储接口 → 数据库或外部服务。浏览器负责展示与实验交互，正式评分、权限和签到有效性由服务端判定。

知识掌握是基于作答证据的形成性反馈。浏览页面、实验保存次数和自由文本结论不会自动变成能力分数。

## 4. 三次完整实验与编程

入口为 `/learn/experiments`，每次实验四项任务，共 12 项：

| 实验 | 任务 |
| --- | --- |
| 实验一：信号变换与连续系统时域探究 | L1-1 信号变换与窄脉冲；L1-2 系统性质检验；L1-3 初始状态与响应分解；L1-4 卷积与心电滑动平均。 |
| 实验二：信号分解、频谱与滤波 | L2-1 方波谐波合成；L2-2 矩形脉冲及连续频谱；L2-3 心电工频陷波设计；L2-4 采样与混叠。 |
| 实验三：拉普拉斯变换与连续系统响应求解 | L3-1 时域信号与拉氏变换对应；L3-2 一阶系统响应；L3-3 心电陷波零极点；L3-4 脉冲持续时间设计。 |

工作台包含预测、分组操作、参数调整、图形、游标、读数与单位核对、系数填写、对照记录、结论和推导。部分任务包含音频混叠试听与合成心电信号分析。

过程材料按账号保存，支持刷新恢复、跨设备继续、保存失败重试、多窗口冲突提示、JSON 导入导出、当前实验打印报告，以及旧版本记录归档。导入不会把历史过程材料兑换成正式成绩。

Python 编程集中在“学习实验室 → 学习工具 → Python 编程资源”：提供独立编辑、运行、输出和图形，以及三份 `.py`、三份 Notebook 和整包下载。三次实验工作台内不再嵌入 Python 编辑器或运行区，实验报告不展示 Python；旧数据仍保留于 JSON，避免影响已有实验材料。独立页面的草稿不自动进入实验记录。浏览器首次加载 Python 环境需要访问资源 CDN，后端不执行学生 Python 代码。

教师指南由受权限保护的接口提供，覆盖课堂组织、全部任务、检查点与样题参考，可打印。教师目录显示“教学预览”，学生目录显示本班实际开放状态。

## 5. 实验正式验收与评分

- 教师按班级发布实验验收，设置开始时间、可选截止时间和开放状态。
- 服务端为全部 12 项任务生成试题、核对答案并评分，学生提交前不返回标准答案。
- 每项任务操作检查点共 5 分，独立验收 15 分、规律判断 5 分；四项合计 100 分。
- 每项最多两次正式验收，采用不同参数；取较高的一次整卷成绩，不拼接各次最优字段。
- 支持逐字段反馈、部分得分、重复提交处理；主动查看完整解析会结束剩余验收机会。
- 教师可查看班级成绩、学生原始提交、参考样题，并填写原因更正分数，保留原分和更正记录。
- 班级实验开关也约束评分写入；过程自查、预测文字、导入 JSON 和 Python 运行结果不直接计入正式分数。

主要实现：`backend/internal/domain/labassessment/`、`application/labassessment/`，前端 `learning-lab-assessment.tsx` 和 `classroom-lab-assessments.tsx`。

## 7. 课堂签到

- 教师入口：班级详情 → 签到考勤；学生入口：课堂活动。
- 场次时长 1～180 分钟，可设置迟到起点；发起时固定应到名单。
- 二维码与六位码每 30 秒更新，学生登录后确认本人签到。
- 签到绑定本人账号和班级成员关系，要求已完成初始改密；服务端控制有效时间与尝试次数。
- 重复签到保留首次结果，到期或手动关闭后停止接收。
- 显示应到、已到、未到、请假，支持筛选和 CSV 导出。
- 教师可更正为已到、迟到、缺勤、请假，必须填写原因，保留操作人和修改历史。

网页签到确认的是登录账号取得课堂凭证，不能单独证明本人到场，仍可结合点名抽查。详细说明见 [课堂签到与身份核验](课堂签到与身份核验.md)。

课程正文阅读和确定性评分无需 AI。基于知识库的问答需要已上传资料、Embedding 配置、检索索引，以及可用的对话模型。旧自动导入的保留库 `kb_signals_systems` 已增加停用迁移；教师同名手动库不按名称删除。

模型适配代码涵盖 OpenAI 兼容 Chat Completions / Responses、Anthropic、Gemini、OpenRouter、xAI 等。具体工具、多模态和推理能力取决于模型、路由协议及启用配置。

## 9. 账号、后台和配置

账号体系支持普通用户、学生、教师、管理员、超级管理员，以及账号状态控制。已有用户名/邮箱登录、首次设置、资料头像、修改用户名和密码、邮箱验证、找回密码、第三方身份绑定、两步验证与恢复码、设备会话管理、退出其他设备和注销账号等实现；邮件与第三方登录需要相应服务配置。

当前后台网页只展示四个主栏目：

| 栏目 | 功能 |
| --- | --- |
| 账号 | 创建、编辑、名单导入、角色与状态管理、密码/两步验证重置和会话撤销。 |

## 10. 桌面端、部署与运行能力

- Web 支持桌面和手机浏览器、浅色/深色、中英界面以及品牌与 PWA 图标配置；不等于所有功能都能离线使用。
- Tauri 桌面端复用 Web，可连接远程服务器，也可启动内置 Go / SQLite 服务；支持多服务器标签页、凭证隔离、系统密钥存储、托盘、OAuth 回环和按发行形式更新。
- 桌面本地模式通过服务器能力声明隐藏多用户和部分账户安全管理，不等同于多人课堂服务器。
- 包含 Windows、macOS、Linux 构建工作流；Windows 有安装版、便携布局与组策略相关支持。
- 数据库支持 PostgreSQL + pgvector 或 SQLite + sqlite-vec；缓存支持 Redis 或进程内存；文件存储支持本地目录或 S3 兼容服务。
- Docker 有轻量 SQLite、外部 PostgreSQL / Redis、完整依赖栈方案；文档解析/OCR 服务可选。
- 提供健康检查、就绪检查、版本接口、开发 Swagger、结构化日志、请求标识、审计、OpenTelemetry 和后台任务。
- API 类型由 Swagger 生成；CI 包含前后端检查、测试、架构约束、构建、镜像与桌面发布流程。仓库存在工作流不代表本次已触发发布。

## 13. 当前边界与本次试用

1. 原生移动 App 尚未实现，仓库当前只有 `apps/web` 和 `apps/desktop`。
2. 没有完整的支付、余额、套餐或兑换码系统，`billingGating` 能力恒为 false。
3. 没有学生人脸核验、校园统一身份认证自动绑定或可靠的物理到场证明；现有第三方身份接口不等于已经接入学校。
4. 实验正式数值评分已实现，但不包含通用手写识别、任意推导证明判分或自由文本报告的可信自动评分。
5. 随机点名当前为本轮页面历史；持久化考勤由独立签到模块提供。
