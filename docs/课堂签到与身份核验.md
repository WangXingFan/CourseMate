# 课堂签到与身份核验

## 教师操作

1. 在“班级 → 签到考勤”中发起签到，填写名称和签到时长（1～180 分钟）。迟到起点按开始后的分钟数填写，0 表示不区分迟到。
2. 点击“投屏显示”进入全屏：左半屏展示大号六位签到码和二维码，右半屏默认显示已签到人员名单，点击“未签到”可切换名单。名单每 3 秒自动更新，已签到包含迟到及教师补记的已到人员，请假人员单独计数、不列入未签到。凭证每 30 秒更新；学生也可以直接进入“课堂活动”输入数字码。按 Esc 或点击“退出投屏”返回；浏览器不支持全屏时使用铺满页面的投屏视图。
3. 查看应到、已到、未到、请假统计，点击统计项筛选名单。已到包含正常签到与迟到。
4. 到期自动停止接收签到，也可提前点击“结束签到”。展开学生记录可补记或更正为已到、迟到、缺勤、请假，必须填写原因。
5. 导出 CSV 保存考勤结果。更正历史保留操作人、时间、修改前后的状态和原因。

## 学生操作

登录本人账号，进入“课堂活动”，或扫描教师展示的二维码。确认页面上的姓名和学号/账号，再点击“确认本人签到”。扫码时未登录会先进入登录流程；若登录后凭证已经过期，输入投屏上的最新数字码即可。

签到使用服务器时间。重复提交返回已有结果，不会改变首次签到时间或覆盖教师更正。新加入班级的学生不会自动进入已经发起的签到场次，可由教师重新发起场次。

## 身份与权限

- 签到绑定登录账号的稳定学生 ID，不能通过提交姓名或学号替他人签到。必须在发起时的应到名单中，且提交时仍属于该班级。
- 新建、导入学生账号时，每人生成独立随机初始密码，首次登录必须修改。教师应核对身份后单独发放凭证；导出的密码文件不适合公开分享。已有账号密码不自动改变。
- 网页签到证明账号持有人取得了课堂凭证，无法单独证明学生本人到场。动态码能缩短转发窗口，可结合现有随机点名抽查。
- 教师只能管理本人班级的签到；学生接口只返回本人的考勤，不返回教师签到码或场次密钥。每名学生每轮凭证最多尝试 5 次。

## 数据与接口

启动时通过现有 schema 迁移创建 `classroom_attendance_sessions` 和 `classroom_attendance_records`。发起场次时固定应到名单，后续移出学生或修改姓名不改变历史名单。签到、关闭与更正在数据库中串行写入，兼容 SQLite 和 PostgreSQL。

教师接口：

- `GET/POST /api/v1/classrooms/:id/attendance`：查询、发起。
- `GET /api/v1/attendance/:id`：名单、当前凭证和服务器时间。
- `POST /api/v1/attendance/:id/close`：提前结束。
- `PUT /api/v1/attendance/:id/students/:student_id`：更正。

学生接口：`GET /api/v1/student/attendance`、`POST /api/v1/student/attendance/:id/check-in`。请求和响应定义以生成的 Swagger 为准。

## 升级兼容

- 后端升级启动时，删除旧自动导入库 `kb_signals_systems` 及其知识库文件关联，并从数据库中的默认检索配置移除该 ID；已停用的旧库同样清理。保留文件对象，不影响其他库引用的资料；不会按名称匹配教师手动创建的“信号与系统”。知识库由教师自行添加。若配置文件仍显式引用旧 ID，应改为手动上传库的 ID。
- 实验页对教师、管理员显示“教学预览”。班级页开关决定学生访问权限，教师预览不表示已对学生开放。
